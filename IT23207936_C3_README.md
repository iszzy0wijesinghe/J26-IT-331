## 1. Research Overview

Component 3 (C3) focuses on developing and evaluating an intelligent temporal forecasting approach for landslide-monitoring sensor networks.

The component investigates how multi-sensor observations collected at variable time intervals can be used to forecast future soil-moisture conditions. A central research consideration is that energy-aware monitoring devices may change their data collection frequency according to environmental risk and operating mode.

Unlike approaches that implicitly treat consecutive observations as equally spaced, C3 explicitly investigates elapsed-time information and operating-mode context during multivariate temporal forecasting.

The component is designed as an independently executable, trainable, testable and demonstrable research module, while preserving interfaces for optional integration with other GeoNex components.

## 2. Research Problem and Gap

Energy-constrained IoT landslide-monitoring systems may use different sensing intervals depending on environmental conditions.

This introduces several temporal forecasting challenges:

1. Consecutive sensor readings are not necessarily separated by equal time intervals.
2. Sequences containing equal numbers of observations can cover substantially different durations.
3. Conventional recurrent forecasting models do not inherently account for actual elapsed time or operating-mode transitions.
4. Environmental changes, sensor noise and variable observation availability complicate future-state estimation.
5. Forecasts must remain interpretable at fixed future time horizons even when the observation schedule changes.

Existing research already addresses irregular time-series modeling and adaptive sensor sampling. Therefore, C3 does not claim to have invented these concepts.

The specific research investigation concerns their combined use in risk-driven, mode-conditioned, multivariate landslide-monitoring sensor forecasting.

## 3. Research Objective

To develop and evaluate a mode-conditioned multivariate forecasting approach that incorporates elapsed time and sensor operating-mode information to predict future soil-moisture conditions at multiple time horizons while supporting energy-aware sensor monitoring.

### Specific Objectives

- Represent variable-rate multi-sensor histories without assuming fixed observation intervals.
- Construct temporal features incorporating sensor measurements, validity information, elapsed time and operating-mode context.
- Forecast soil-moisture conditions at +15, +30 and +60 minutes.
- Compare non-learning, traditional machine-learning and deep-learning forecasting approaches.
- Evaluate the contribution of time and operating-mode features through controlled ablation studies.
- Preserve forecast metadata, model versions and historical observation context for research reproducibility.

## 4. Proposed Research Contributions and Novelty

The proposed C3 contribution is a unified experimental approach combining:

**Variable-rate temporal representation:** Historical sensor observations retain chronological ordering and elapsed-time information.

**Operating-mode-conditioned forecasting:** The approach investigates whether device operating modes provide useful context for interpreting environmental changes.

**Multi-sensor learning:** Soil moisture, rainfall proxy, tilt, vibration, force-sensitive resistance, air temperature and humidity are considered together rather than independently.

**Multi-horizon prediction:** Forecasting is investigated at three fixed elapsed-time horizons: 15, 30 and 60 minutes.

**Controlled comparative evaluation:** Different model families and M4 feature ablations allow the effects of model complexity, time context and mode context to be evaluated.

These represent proposed research contributions. Their novelty relative to published work and their empirical forecasting advantage require literature-backed comparison and experimental validation.

## 5. Sensor Data and Operating Context

The C3 sensor features include:

| Feature | Purpose |
|---|---|
| Soil moisture | Primary forecasting target and historical input |
| Rainfall proxy counts | Rainfall-related environmental context |
| Tilt | Ground-orientation or movement-related observations |
| Vibration | Mechanical disturbance observations |
| FSR ADC | Force or pressure-related measurements |
| Air temperature | Environmental context |
| Humidity | Atmospheric moisture context |

The broader research design considers risk-driven operating modes with different observation frequencies.

The current documented Golden Dataset compatibility path includes DEEP_SLEEP, IDLE, RISK and WARNING. EMERGENCY belongs to the wider design and requires separate implementation and evaluation coverage.

## 6. AI, ML and Deep Learning Methodology

Five model groups (M0–M4) are documented in the existing experimental plan. A subsequent commit mentions planning for an additional model, but it is not treated as an implemented or validated model.

| ID | Model | Role |
|---|---|---|
| M0 | Strict Persistence Forecasting | Non-learning reference baseline |
| M1 | Ridge Regression | Regularized linear machine-learning baseline |
| M2 | Histogram Gradient Boosting | Nonlinear tabular machine-learning baseline |
| M3 | Standard GRU | Recurrent deep-learning baseline |
| M4 | Time- and Mode-Aware GRU | Proposed research model family |

### M0 — Strict Persistence

Predicts future soil moisture using the latest eligible historical observation.

The implemented baseline rejects observations that are missing, imputed, corrected or unavailable at the forecast origin.

### M1 — Ridge Regression

Uses engineered tabular historical features and L2-regularized regression to establish a lightweight linear benchmark.

### M2 — Histogram Gradient Boosting

Uses engineered tabular features and nonlinear gradient-boosted decision trees to investigate relationships beyond a linear model.

### M3 — Standard GRU

Uses chronological multi-sensor observations and validity masks to learn sequential relationships.

The current inference implementation expects 14 input features per timestep: seven sensor measurements and seven validity masks.

### M4 — Time- and Mode-Aware GRU

The proposed research model family extends sequence-based forecasting through explicit temporal and/or operating-mode information.

The current feature ablations are:

- **M4-A:** Time-aware features without operating-mode encoding.
- **M4-B:** Mode-aware features without explicit elapsed-time features.
- **M4-C:** Combined elapsed-time and operating-mode features.

M4-C represents the combined time-and-mode configuration.

## 7. Forecasting Methodology

The implemented forecasting workflow follows these main stages:

1. Select an existing Golden Dataset, device, episode and forecast origin.
2. Retrieve historical observations without including future measurements.
3. Reconstruct the model-compatible temporal sequence.
4. Extract tabular or recurrent features according to the selected model.
5. Load a previously trained model checkpoint.
6. Generate predictions for the configured forecasting horizons.
7. Associate forecasts with their model versions, target timestamps and historical context.
8. Evaluate results against eligible observed targets when available.

The component maintains a separation between offline model training, research evaluation and inference.

The existing project implementation demonstrates substantial progress toward a complete C3 research workflow.

- Multi-horizon model artifacts for +15, +30 and +60 minutes.
- A forecasting adapter that prepares training-compatible model inputs.
- Tabular feature extraction with a validated 79-feature schema.
- Standard GRU sequence preparation using 14-feature inputs.
- M4 ablation sequence preparation using 20-feature inputs.
- Checkpoint-based inference implementations for recurrent models.
- Model registration and activation-related Workbench modules.
- A historical-replay forecasting engine with checkpoint verification.
- Forecast generation and retrieval API endpoints.
- Unit and integration test modules related to C3 training and inference.

### Current research safeguards

The existing code includes safeguards for:

- Historical-only forecasting inputs.
- Separation of dataset, device and episode histories.
- Model horizon consistency.
- Expected feature-schema validation.
- Finite numerical predictions.
- Checkpoint file integrity checks.
- Distinguishing synthetic sensor forecasting from validated landslide-event prediction.

The presence of these implementations is supported by the inspected repository code and model artifacts. Formal test-pass rates and forecasting performance results should be reported separately using reproducible experiment outputs.

## 14. Research Scope and Limitations

The current experimental workflow includes synthetic-data research evaluation.

The current forecasting target is future soil moisture, not a validated landslide probability, landslide occurrence time or public safety alert.

Consequently, demonstrated sensor-value forecasting must not be interpreted as proven landslide-event prediction.

The research aims to advance from controlled synthetic experiments toward stronger independent evaluation and real-world validation.

## 15. Research Direction

GeoNex C3 has progressed beyond the conceptual stage into a structured forecasting research implementation with multiple model families, saved checkpoints, feature-processing pipelines, historical-replay inference infrastructure and model-management capabilities.

The next development stage focuses on strengthening comparative evidence, validating the proposed time-and-mode-aware forecasting contribution, improving demonstration reproducibility and evaluating its suitability for real sensor conditions.

The central research goal remains the same: **reliable and explainable multivariate forecasting under variable-rate, mode-conditioned sensing conditions.**
